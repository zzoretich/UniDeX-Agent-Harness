# Code chat view Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agent terminals on the Code tab show a chat laid out like the Claude Code app, drawn from the host's own
transcript, while the real `claude` / `codex` process keeps running one ⌘J away. The same release adds history in the
sidebar, approval cards, the exact status line, Diff and Files panes, and images in the composer.

**Architecture:** The runtime turns transcripts into the existing session-event shape and writes them to
`brain/_index/code/*.jsonl` (host-parity Q4: the app never reads a transcript). Main spawns one follower per agent
terminal, and the HUD tails the cache and draws it with Sessions' `threadRows` through an extracted `ThreadView`.
Approval prompts and Codex's footer come from a headless xterm per agent terminal. Claude's status line comes from a
per-terminal copy that `aos statusline render` writes.

**Tech Stack:** Node ≥ 20 CommonJS runtime (`node:test`); Electron main and HUD in TypeScript; xterm 5.5 plus one new
dependency, `@xterm/headless`; Playwright e2e.

**Spec:** `docs/design/specs/2026-11-09-code-chat-design.md` (C1–C13 below refer to its decisions).

## Global Constraints

- Runtime, `cli` and `tools`: Node ≥ 20, CommonJS, **no new runtime dependency**, `node:test` + `node:assert/strict`, no
  network in tests.
- App and HUD: the one new dependency is `@xterm/headless` `^5.5.0`, added to both `hud/package.json` and
  `app/package.json` beside `@xterm/xterm`.
- Paths: no absolute home paths in code, tests or docs. Tests use `os.tmpdir()`.
- Colours come only from `hud/src/ui/tokens.ts`, light and dark (C9). The HUD's `check:hex` step fails any raw hex.
- **Never run a test bare.** Use `npm test`, or for one runtime file `node --require ./tools/test-env.js --test <file>`
  from the repo root. For one HUD file: `cd hud && node --require ../tools/test-env.js --import tsx --test <file>`.
- `aos statusline render` keeps its contract: its stdout and exit code never change because of the tee. Every failure in
  the tee is swallowed.
- Fixed values:
  - follower poll: 250 ms
  - past conversations per group: 10
  - group window: 14 days
  - prune `brain/_index/code` after 14 days and `brain/_index/statusline` after 24 h
  - chat row cap: 400, with "Show earlier"
  - images: PNG, JPEG, GIF or WebP, up to 10 MB
  - layout: chat column 760 px, sidebar 264 px, top bar 48 px
- Exact copy:
  - "Waiting on you in the terminal"
  - "Answer in the terminal ⌘J"
  - "No chat for this session yet · Terminal ⌘J"
  - "Can't tell which conversation · Terminal ⌘J"
  - "Status line in the terminal ⌘J"
  - "Chat view is off · Settings"
  - "Show more"
  - "All history"
  - "Other folders"
  - "Show earlier"
- Ids:
  - `AOS_TERMINAL`: a v4 UUID, `/^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$/`
  - session ids: `/^[A-Za-z0-9._-]{1,128}$/` with no `..`
- Every new IPC channel needs:
  - its `CH` entry and its `AosBridge` type in `src/shared/ipc.ts`
  - a named preload function
  - a zod schema in `src/main/ipc/schemas.ts`
  - its handler through `trust.ts`
  - its line in `tests/e2e/sandbox.spec.ts`
- `plugin/` and `codex-plugin/` are untouched: `npm run build:codex-plugin` leaves no diff.
- Commits: the noreply identity, a `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` trailer only, never
  `--no-verify`.
- CHANGELOG Added and Changed bullets end with a `<!-- tour: … -->` or `<!-- no-tour: … -->` marker.

### Task 2: `mirror` follower and caches

**Files:**
- Create `brain/scripts/lib/code-mirror.js`.
- Modify `brain/scripts/lib/sessions.js` (the `mirror` verb and its usage line) and `brain/scripts/scan-vault.js`.

**Interfaces:**
- Consumes: `createTranscriptMapper` from T1; `H.findTranscript`, `H.sessionFiles` and `H.hostDirs` from `lib/host.js`;
  `writeAtomic` from `lib/fsx.js`.
- Produces:
  - `cachePath(vault, key) → string`, i.e. `<vault>/brain/_index/code/<key>.jsonl`. The key is a terminal UUID, or
    `<host>-<sessionId>`.
  - `pickCodexRollout(cands: {file, cwd, startedAt: number, mtimeMs: number}[], { cwd, since: number, claimed: Set<string> }) → { file } | { ambiguous: true } | null`
  - `mirrorOnce({ host, id, vault, dirs }) → { ok: true, cache } | { ok: false, reason }`
  - `follow({ host, terminal, id?, cwd?, since?, vault, dirs, pollMs = 250, signal }) → Promise<void>`
  - `readTee(vault, terminal) → { at, session_id, transcript_path, ansi } | null`
  - `pruneCodeCaches(vault, { now, codeDays = 14, statusHours = 24 }) → { pruned: number }`
- CLI: `sessions.js mirror --host claude|codex (--id <id> | --cwd <abs> --since <ms>) [--terminal <uuid>] (--once|--follow)`.
  It exits 2 on bad arguments and 0 when it ends.

**Behaviour:**
- `--once` writes the whole cache atomically.
- `--follow` writes the transcript's events so far, then appends the events of each complete new line. A partial last
  line waits for its newline.
- **Claude** follow: on each poll, `readTee` is checked. When `session_id` differs, it switches to that transcript
  (found with `findTranscript`, never the tee's raw path when it lies outside `hostDirs`) and writes a `session` event
  first.
- **Codex** follow: in folder mode, it follows `pickCodexRollout` among rollouts whose `session_meta.cwd === cwd` and that
  were modified at or after `since`, preferring the most recently appended. "Ambiguous" means two or more candidates
  that started within the same 5 s and are both being appended. In that case it writes
  `{kind:'error', message:"Can't tell which conversation · Terminal ⌘J"}` once and keeps polling.
- The loop exits on SIGTERM, an aborted `signal`, or a transcript that is gone for 10 polls.
