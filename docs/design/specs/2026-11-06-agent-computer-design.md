## 1. Problem

At d495ded the Chief of Staff (injected into every Chat and Code session on both hosts, `docs/chief-of-staff.md` "Every session") can only act through its host's shell and file tools on the real Mac:

1. **It can't see what it builds.** A Code session that starts a dev server can't open it, click through it or screenshot it; the user opens a browser and describes what they see.
2. **No shared web.** Research and tasks on signed-in sites (dashboards, admin consoles, GitHub) happen in the user's own browser, out of the agent's sight.
3. **No safe place for risky code.** Untrusted repos, installers and experiments run on the real Mac, limited only by the access chip (Read only, Edit files, Run commands) and Codex's own sandbox. *(Not addressed: the sandbox machine was dropped on 2026-11-07.)*
4. **No computer use.** Native apps (Numbers, Finder, System Settings) are out of reach.

The app is deliberately closed: the page runs sandboxed with `webviewTag: false`, and main refuses remote-debugging switches. Any browser added must be its own locked-down surface.

## 4. Design

### 4.1 The pane (HUD)
`hud/src/ui/ComputerPane.ts`, mounted by `TermTab` and `SessionsTab` beside the terminal or reader; width remembered per tab. It renders the header, tabs, driving bar, ask cards and footer, and reserves a rectangle that main fills with the native view (bounds sent over IPC on every layout change). Pop-out moves the views into a child window. The pane shows the selected session's workspace computer; the mode switch shows that session's mode.

### 4.2 Browser (main, release 1)
`app/src/main/computer/browser.ts`: `WebContentsView`s in partition `persist:computer` `sandbox: true`, no preload, permissions denied except through D6, downloads and new windows held for D6 and the pane's tabs. **Navigation allows only `http:` and `https:`**, plus the app's own validated sandbox-preview route (D40): `javascript:`, `data:`, `blob:`, `file:`, `agenticos:`, `chrome:`, `devtools:` and `about:` other than `about:blank` are refused for agent opens, redirects, page navigations and new windows. One set of tabs per workspace.

### 4.3 Bridge and tools
`app/src/main/computer/bridge.ts` serves JSON lines on the socket, admits per D18 through `app/native/peer` (a small N-API addon: peer PID, parent chain, argv), and routes each call to the calling session's workspace computer and mode. MCP tools (both hosts):
`computer_status` · `computer_open` · `computer_snapshot` · `computer_screenshot` · `computer_click` · `computer_type` · `computer_key` · `computer_scroll` · `computer_wait` (a page condition or an ask id, D34), which target the browser or, in Your Mac mode, the screen. Without the app, or from an unadmitted process, every tool replies in one line how to get it.

### 4.4 Ask gate
Before any input is delivered, main applies D39 (the site's mark, then the D6 categories from the target's role, label, form and file input) and, in Your Mac mode, the helper applies D42 (the accessibility element under the point, and the key). The gate holds the call, shows the card (and, off-screen, D27's notification), writes the line (a Chat thread's event stream, or the Code pane's activity log, D35), and answers per D34. "Always on `<site>`" is stored per origin in the app's user data.

### 4.5 Sandbox (dropped 2026-11-07)
The owner dropped the sandbox machine; nothing in this section is built.

### 4.6 Your Mac (release 2)
The same helper, under its own identity (D37), captures the display (ScreenCaptureKit) and posts input (CGEvent) after macOS grants it Screen Recording and Accessibility; without them the switch's Your Mac side is disabled with a fix-it link. The glow is a click-through overlay window per display.

## 5. Host parity

1. **Entry point:** no command; the user opens the pane on the Code or Chat page, and the agent calls the MCP tools, pre-approved in Workbench sessions on both hosts (D33; Codex in plugin and direct mode, applied by `aos upgrade`). Claude Code: `mcp__plugin_agenticos_agenticos__computer_*`; Codex plugin and direct mode: `mcp__agenticos__computer_*`.
2. **Hooks:** none added or changed.
3. **Model calls:** none; screenshots and snapshots are ordinary tool results inside the session's own turns and spend.
4. **Session data:** no transcript reads; the bridge identifies sessions by process ancestry (D18).
5. **MCP:** nine new tools in the existing server; no skill names them, so no generated text changes.
6. **Degradation:** a session outside the app, a Read only session (D17), missing macOS permissions (§4.6), a busy computer (D31) and an unmarked site's pending ask (D39) each get a visible one-line state, never a silent no-op. Codex parity is proven before release 1 merges (D33).
7. **Docs:** README, `docs/app-smoke.md` items per host and their `COVERAGE.md` rows, `SECURITY.md` (the new view, socket, helper and entitlement), `app/README.md`, tour steps.

## 6. Acceptance and verification

**Release 1 (Browser).** A Chat turn and a Code session on each host open a page in the pane, snapshot it and click; a flagged click shows the ask card, Deny leaves the page unchanged and Allow proceeds; on an unmarked site any click or typing asks first, including a "Continue" button that would fire a same-origin `fetch` POST, while opening, scrolling and snapshots don't (D39); an approval after Take over or a wheel change is cancelled (D31); Take over stops the next action within 100 ms; an off-screen ask raises the notification and badge (D27); a second session gets "busy" (D31); a Read only session can snapshot but not click (D17); a process outside the app, an npm script run in a Code terminal, and a program presenting forged CLI argv are refused, while an npm-installed Claude Code or Codex is admitted (D18); password fields come back redacted in snapshots and masked in screenshots, also after a Show password reveal (D9); on an unmarked site Tab-then-Space onto a button asks, and so does `computer_type` into a field, tested apart from `computer_key` (D39); on a marked site "Merge pull request", "Sign in", a download, and Return in an ordinary form field each ask (D39, D43); `computer_open` refuses `javascript:` and `data:` URLs and a redirect to one (§4.2).
**Release 2 (Sandbox).** Dropped by the owner on 2026-11-07.
**Release 2 (Your Mac).** The switch confirms once per session and logs the flip; a click on an unlabeled control or on Mail's Send asks before delivery, as do Space or Return with Send focused, Return or `computer_type` text containing a newline (one ask per call), a "Merge" button and a system permission dialog, and a click on a labeled ordinary control does not (D42, D43); the glow and mirror appear; Esc and any user input take over; Screen Recording and Accessibility are granted to UniDeX Computer, not the app, and a shell in a Code terminal cannot capture the screen (D37).
