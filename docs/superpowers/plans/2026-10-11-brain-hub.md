### Mechanics

**Paths.** `PATH` = `^brain/memory/(user|feedback|projects|reference)/[a-z0-9][a-z0-9.-]{0,120}\.md$` (every memory on a real vault matches; `README.md` never does). `SLUG` (drafts) = `^[a-z0-9][a-z0-9.-]{0,120}$`. The type folder must pass `runtimeDir` (plain folders, realpath inside the vault); the file is read `O_NOFOLLOW` and must be regular; writes are `fsx.writeAtomic` (a link appearing there is replaced, never written through).

**Frontmatter edits** touch only these keys, line by line, keeping every other byte: `reviewed`, `pin`, `description`, `status_before`, `archived`, `superseded_by`, and the `status/<x>` entry inside `tags: [...]` (appended when missing). `updated:` is not bumped (it orders Active context by content changes).

**Verbs** (`--json` prints one object; errors go to stderr as `aos: <msg>`, exit 1; usage, exit 2):

| Verb | Writes | JSON |
|---|---|---|
| `list [--json]` | nothing | `{schema:1, memories:[{path,type,title,description,status,pin,reviewed,source,session,created,updated,hash}], drafts:[{slug,title,description,created}], counts}` |
| `keep PATH… --json` | `reviewed: true`; trail `kept` | `{kept, already}` |
| `set PATH --set JSON_OBJ --expect HASH [--dry-run] --json` | keys `pin` (bool), `status` (active·complete·paused), `description` (≤ 200 chars, one line; also the MEMORY.md line); trail `set`; rebuilds BRAIN.md | `{path, fields, written, hash, text?, beforeText?, brainMd}` |
| `archive PATH… --json` | `description:` copied from MEMORY.md when missing, `status_before`, `archived: <date>`, `status/archived`; MEMORY.md line removed; trail `archived`; rebuild | `{archived, already, brainMd}` |
| `restore PATH… --json` | the status back (`status_before`, else active), those keys and `superseded_by` removed; MEMORY.md line re-added from the H1 and `description:`; trail `restored`; rebuild | `{restored, already, brainMd}` |
| `supersede PATH --by PATH --json` | as archive, with `status/superseded` and `superseded_by:`; refuses itself, a missing or non-live winner | `{path, by, brainMd}` |
| `draft approve\|reject SLUG --json` | `feedback-drafts.js` `applyDraft` / `rejectDraft` (today's writes) | `{approved: path}` / `{rejected: slug}` |
| `notdup PATH PATH --json` | `brain/_index/memory-notdup.json` (`{schema:1, pairs:[[a,b]]}`, sorted pair) | `{pair, added}` |

`set --expect` takes `HASH_RE` (`none` or 16–64 hex): the file's sha256 as `list` printed it; a changed file is refused. The other writing verbs check the live state instead (already kept, already archived).

**Usage log (D8, D9).** Row `{ts, host, how, path}`, one per path, `how` ∈ injected · recalled · read, `path` under `brain/memory/` or `brain/patterns/` only. `inject-context.js` logs after its stdout write: `brain-sources.json`'s who, rules and active paths (when BRAIN.md was injected) and the paths in `recall-wake.md` (when its block was). The MCP server logs `recall` hits and a found `memory_read`. Off when `telemetry.enabled` is false. Every failure is swallowed (a hook exits 0 with nothing extra on stdout). `foldUsage` (scan) moves rows older than `memory.usageDays` into `memory-usage-rollup.json` (`{schema:1, through, paths:{p:{injected,recalled,read,claude,codex,last}}}`) under the log's lock.

**`brain-sources.json` (D10).** `{schema:1, builtAt, budget, tokens, sections:{who:{paths,tokens}, rules:{paths,tokens}, active:{paths,omitted,tokens}, links:{tokens}, lastSession:{tokens}}}`, written after BRAIN.md under no lock of its own (one writer).

**`brain-hub.json` (D11, D12).** `{schema:1, builtAt, counts:{memories, byType, unreviewed, drafts, patterns, reflections, archived, superseded}, batches:[{key, session, host, title, at, paths}], dups:[{a, b, score, title, text, meaning}], clusters:[{paths, label}], usage:{since, paths:{p:{d7, d30, last, injected, recalled, read, claude, codex}}}, hygiene:{sources, oldType, noDescription, unindexed, misfiled, leftoverDrafts}, shipped:[{path, why}]}`.
- Batches: unreviewed live memories grouped by `session:`; title and host from `session-index.json` (by `head.id`), else `in-session · <date>` / `<date>`; `at` from the trail's `written` row, else `created`; newest first.
- Duplicates: title Jaccard (`noise-gate.js`), tf-idf cosine over the recall index's `tf`, embedding cosine (mean of a path's chunks) when the index has the path. `score` = max(meaning, 0.55·text + 0.45·title); pairs ≥ `memory.dupScore`, not in `memory-notdup.json`, both live. Clusters: connected components of pairs ≥ 0.7 with ≥ `memory.clusterMin` members, labelled by their shared title words.
- Shipped: a live `status/active` project whose title or index description names a version (`v?\d+\.\d+`), "shipped", "released" or "merged".

**Tests.** memory-ops: every verb's write on a temp vault, idempotence, a symlinked memory and a symlinked type folder refused, an outside or README path refused, `--expect` mismatch, MEMORY.md upsert never duplicates, restore re-adds the line, BRAIN.md skips archived pins. memory-usage: per host (`AOS_HOST` claude and codex), telemetry off, non-memory paths dropped, fold moves old rows. inject-context: rows after an injection, none on the second turn, stdout unchanged. mcp-server: `recall` and `memory_read` rows. brain-hub: batches, a known duplicate pair with and without an embed index, notdup respected, shipped. cli/memory: argument rules, JSON shapes, exit codes. Rehearsals: a `recall` through the MCP server leaves a `host:"claude"` row (first-run) and a `host:"codex"` row (codex-host).

### Mechanics

**Decisions made here.** Hygiene fixes are not undoable (user, 2026-10-11): each shows its dry run and asks first (`ConfirmModal`, spec §6), and each changed file gets a trail row naming the field and its before and after. The Map keeps graphify's own communities (Leiden over the whole graph): re-clustering the memories alone, once the index hubs are out, left one group of eight on the real vault, while graphify's gave five of 9–13 (and fourteen at `mapMin` 5).

**`aos memory fix <kind> [--dry-run] [--json]`** (`cli/memory.js` → `lib/memory-fix.js`). It re-reads the files (never `brain-hub.json`) through `lib/memory-hygiene.js`, which `brain-hub.js` uses for its `hygiene` too, so the two always agree. Only live memories (never archived or superseded) and only the keys named here change; every other byte stays. A dry run computes the same changes on the texts it read and writes nothing (no file, no trail row). A second run finds nothing to do (`changes: []`).

| Kind | Finds (hygiene key) | Changes | `changes[]` rows |
|---|---|---|---|
| `sources` | `source:` ∈ `session`, `in-session`, `wrap` (all in-session writes) | `source: manual-wrap` (what `/wrap` writes; `auto-wrap` and no source stay) | `{path, action:"source", before, after}` |
| `types` | `oldType`: frontmatter whose top-level `type:` is not `memory` or is missing (a host's auto-memory shape) | `type: memory` (replaced, or inserted as the first key); `tags:` gains `memory/<type>` (a missing `tags:` becomes `[memory/<type>]`); no status is invented, since `status/active` would put an old project into BRAIN.md's Active context unasked; `name:`, `description:`, `metadata:` stay | `type` (before the old value or null) and, when it changed, `tags` (the old and new line values) |
| `descriptions` | `noDescription`: no `description:` of its own while its MEMORY.md line has one | `description:` = that line's, one line, control characters out, ≤ 200 characters (memory-ops `keepDescription`), quoted only when strict YAML needs it (memory-ops `yamlValue`, also used by `set` and archive) | `{action:"description", before:null, after}` |
| `index` | `unindexed`, `misfiled`, `brokenIndex` | under one MEMORY.md lock: a missing line inserted under its type's heading (`indexLine` from the H1 and the description, else `deriveDescription(firstParagraph)`); a misfiled line moved, text unchanged, under its own heading; a line to a missing file removed | `index-add` (after: the line), `index-move` (before/after: the headings), `index-remove` (path `MEMORY.md`, before: the line) |
| `drafts` | `leftoverDrafts`: a draft whose slug is a live feedback memory | the draft file removed (regular file, plain folder, O_NOFOLLOW read; spec §6's one delete) | `{path:"brain/memory/feedback/_drafts/<slug>.md", action:"draft-remove", before: its title, after:null}` |

JSON (`--json`, both modes): `{kind, dryRun, changes, files, brainMd}`; `files` counts changed files (MEMORY.md once); `brainMd` is build-brain-md's run after a real `types` or `index` run with `files > 0` (`{ok, error?}`), else null. Trail: one row per changed memory or draft, `{action:"fixed", kind, slug, type, title, path, changes:[{field, before, after}]}` through memory-ops `appendTrail` (a draft's row has `type: "feedback"` and its slug; `index-remove` rows have no slug, `path: "MEMORY.md"`). Errors as the other verbs: a usage error exits 2, a refusal (MEMORY.md a link, `brain/_index` missing) `aos: <msg>` exit 1. `--dry-run` is now `set`'s and `fix`'s flag. The HUD shows a `fixed` row in a memory's history as "fixed (<kind>)" (brainModel `historyLine`).

**`brain-map.json`** (`lib/brain-map.js` `buildBrainMap({vault, cfg, memories, now})`, called by `buildBrainHub`, written beside `brain-hub.json` with `fsx.writeAtomic`; the scan's `brain-hub` stage adds it to `wrote`). Input: `<vault>/<graph.out>/graph.json` through `sdk/lib/graph.js` (`outDir`, `loadGraph`) and the live memories (`ops.listMemories`). Shape: `obsidian-plugin/src/data/brainModel.ts` `BrainMap` (the HUD's parser is the contract). Steps:
1. `state`: `"off"` when `graph.enabled === false`; `"missing"` when no readable graph.json; else `"ok"` with `graph: {builtAt, mode, nodes, edges, communities}` (the marker `.aos-graph.json` for `builtAt`/`mode`, else the file's mtime and null). Not ok: every list empty, counts 0.
2. Hubs: nodes whose `source_file` is `MEMORY.md`, `brain/_index/MOC-*.md` or `brain/_index/BRAIN.md`; they and their links are dropped; `hubs` lists the files found. A hub community is any graphify community holding a hub node.
3. Memory units: a live memory's nodes are those whose `source_file` is its path. Memory links: a graph link between nodes of two different live memories (counted), plus two memories sharing one non-memory, non-hub neighbour node (counted once per shared node; a node touching more than 40 memories is a hub-like concept and is skipped).
4. Community: the most common community among a memory's own nodes outside hub communities; else the most common among its linked neighbours' nodes outside hub communities (weighted by link count); ties go to the lower id; none → null. Kept: communities with ≥ `memory.mapMin` memories, as `c<id>`, largest first (ties by id); the rest count in `smaller`, and their memories get `community: null`.
5. Per community: `paths` by degree (distinct linked memories) then path; `lead` the first; `name` its title (memory-ops `titleOf`); `edges` the links inside. `links`: memory links between two kept communities, summed, `a < b`. `memories[p]`: community, degree, ≤ 12 neighbours by count then path. `unlinked`: live memories in the graph with degree 0.
Size on the real vault: about 350 memories, under 100 KB. No model call; deterministic for one graph.

Unit cases: "Brain hub redesign" with "PR #121 merged" is not suggested; "UniDeX 1.5.0 release" and "Workbench proposal (superseded)" are.

**Decisions made while building.**
- `fix index`: a misfiled line of an archived or superseded memory is removed (`index-remove`, path `MEMORY.md`), not moved, since a retired memory has no line (D5, D7); its file is untouched. A line is removed as broken only when nothing at all exists at its path.
- `brain-map.json`: an archived or superseded memory's nodes drop out as if the file were deleted, so a retired memory never links two live ones. The returned hub carries the map unenumerated (`hub.map`) for the scan's report; `brain-hub.json` stays the hub alone.
- Bootstrap computes "looks shipped" from the files with the same `SHIPPED` as `brain-hub.js` (a project marked complete leaves at once, not at the next scan); Active context has All / Looks shipped chips, where "Review the N…" lands.
- "Unused" means one thing across the hub: Library's Use facet and row label follow `memory.neverUsedDays` as Dead weight does (brainModel `usedWithin`; at the default 30 it is the hub's `d30 === 0`), so "Review the N" opens exactly N. MEMORY.md's line count is its non-blank lines in Bootstrap and Health alike (`indexLineCount`).
- An approved feedback draft logs a `written` trail row; `/wrap` (`wrap-session.js`) also rebuilds the hub when it promotes something, logging a failed rebuild to stderr.
