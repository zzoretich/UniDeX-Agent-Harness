### Mechanics

**Paths.** `PATH` = `^brain/memory/(user|feedback|projects|reference)/[a-z0-9][a-z0-9.-]{0,120}\.md$` (every memory on a real vault matches; `README.md` never does). `SLUG` (drafts) = `^[a-z0-9][a-z0-9.-]{0,120}$`. The type folder must pass `runtimeDir` (plain folders, realpath inside the vault); the file is read `O_NOFOLLOW` and must be regular; writes are `fsx.writeAtomic` (a link appearing there is replaced, never written through).

**Frontmatter edits** touch only these keys, line by line, keeping every other byte: `reviewed`, `pin`, `description`, `status_before`, `archived`, `superseded_by`, and the `status/<x>` entry inside `tags: [...]` (appended when missing). `updated:` is not bumped (it orders Active context by content changes).

**Verbs** (`--json` prints one object; errors go to stderr as `aos: <msg>`, exit 1; usage, exit 2):

| Verb | Writes | JSON |
|---|---|---|
| `list [--json]` | nothing | `{schema:1, memories:[{path,type,title,description,status,pin,reviewed,source,session,created,updated,hash}], drafts:[{slug,title,description,created}], counts}` |
| `keep PATH… --json` | `reviewed: true`; trail `kept` | `{kept, already}` |
| `set PATH --set JSON_OBJ --expect HASH [--dry-run] --json` | keys `pin` (bool), `status` (active·complete·paused), `description` (≤ 200 chars, one line; also the MEMORY.md line); trail `set`; rebuilds BRAIN.md | `{path, fields, written, hash, text?, beforeText?, brainMd}` |
| `archive PATH… --json` | `description:` copied from MEMORY.md when missing, `status_before`, `archived: <date>`, `status/archived`; MEMORY.md line removed; trail `archived`; rebuild | `{archived, already, brainMd}` |
| `restore PATH… --json` | the status back (`status_before`, else active), those keys and `superseded_by` removed; MEMORY.md line re-added from the H1 and `description:`; trail `restored`; rebuild | `{restored, already, brainMd}` |
| `supersede PATH --by PATH --json` | as archive, with `status/superseded` and `superseded_by:`; refuses itself, a missing or non-live winner | `{path, by, brainMd}` |
| `draft approve\|reject SLUG --json` | `feedback-drafts.js` `applyDraft` / `rejectDraft` (today's writes) | `{approved: path}` / `{rejected: slug}` |
| `notdup PATH PATH --json` | `brain/_index/memory-notdup.json` (`{schema:1, pairs:[[a,b]]}`, sorted pair) | `{pair, added}` |

`set --expect` takes `HASH_RE` (`none` or 16–64 hex): the file's sha256 as `list` printed it; a changed file is refused. The other writing verbs check the live state instead (already kept, already archived).

**Usage log (D8, D9).** Row `{ts, host, how, path}`, one per path, `how` ∈ injected · recalled · read, `path` under `brain/memory/` or `brain/patterns/` only. `inject-context.js` logs after its stdout write: `brain-sources.json`'s who, rules and active paths (when BRAIN.md was injected) and the paths in `recall-wake.md` (when its block was). The MCP server logs `recall` hits and a found `memory_read`. Off when `telemetry.enabled` is false. Every failure is swallowed (a hook exits 0 with nothing extra on stdout). `foldUsage` (scan) moves rows older than `memory.usageDays` into `memory-usage-rollup.json` (`{schema:1, through, paths:{p:{injected,recalled,read,claude,codex,last}}}`) under the log's lock.

**`brain-sources.json` (D10).** `{schema:1, builtAt, budget, tokens, sections:{who:{paths,tokens}, rules:{paths,tokens}, active:{paths,omitted,tokens}, links:{tokens}, lastSession:{tokens}}}`, written after BRAIN.md under no lock of its own (one writer).

**`brain-hub.json` (D11, D12).** `{schema:1, builtAt, counts:{memories, byType, unreviewed, drafts, patterns, reflections, archived, superseded}, batches:[{key, session, host, title, at, paths}], dups:[{a, b, score, title, text, meaning}], clusters:[{paths, label}], usage:{since, paths:{p:{d7, d30, last, injected, recalled, read, claude, codex}}}, hygiene:{sources, oldType, noDescription, unindexed, misfiled, leftoverDrafts}, shipped:[{path, why}]}`.
- Batches: unreviewed live memories grouped by `session:`; title and host from `session-index.json` (by `head.id`), else `in-session · <date>` / `<date>`; `at` from the trail's `written` row, else `created`; newest first.
- Duplicates: title Jaccard (`noise-gate.js`), tf-idf cosine over the recall index's `tf`, embedding cosine (mean of a path's chunks) when the index has the path. `score` = max(meaning, 0.55·text + 0.45·title); pairs ≥ `memory.dupScore`, not in `memory-notdup.json`, both live. Clusters: connected components of pairs ≥ 0.7 with ≥ `memory.clusterMin` members, labelled by their shared title words.
- Shipped: a live `status/active` project whose title or index description names a version (`v?\d+\.\d+`), "shipped", "released" or "merged".

**Tests.** memory-ops: every verb's write on a temp vault, idempotence, a symlinked memory and a symlinked type folder refused, an outside or README path refused, `--expect` mismatch, MEMORY.md upsert never duplicates, restore re-adds the line, BRAIN.md skips archived pins. memory-usage: per host (`AOS_HOST` claude and codex), telemetry off, non-memory paths dropped, fold moves old rows. inject-context: rows after an injection, none on the second turn, stdout unchanged. mcp-server: `recall` and `memory_read` rows. brain-hub: batches, a known duplicate pair with and without an embed index, notdup respected, shipped. cli/memory: argument rules, JSON shapes, exit codes. Rehearsals: a `recall` through the MCP server leaves a `host:"claude"` row (first-run) and a `host:"codex"` row (codex-host).

### Mechanics

**Decisions made here.** Hygiene fixes are not undoable (user, 2026-10-11): each shows its dry run and asks first (`ConfirmModal`, spec §6), and each changed memory or draft (and each memory whose MEMORY.md lines go) gets a trail row naming the field and its before and after. The Map keeps graphify's own communities (Leiden over the whole graph): re-clustering the memories alone, once the index hubs are out, left one group of eight on the real vault, while graphify's gave five of 9–13 (and fourteen at `mapMin` 5).

**`aos memory fix <kind> [--dry-run] [--expect <hash>] [--json]`** (`cli/memory.js` → `lib/memory-fix.js`). It re-reads the files (never `brain-hub.json`) through `lib/memory-hygiene.js`, which `brain-hub.js` uses for its `hygiene` too, so the two always agree. Only live memories (never archived or superseded) and only the keys named here change; every other byte stays. A dry run computes the same changes on the texts it read and writes nothing (no file, no trail row). A second run finds nothing to do (`changes: []`).

| Kind | Finds (hygiene key) | Changes | `changes[]` rows |
|---|---|---|---|
| `sources` | `source:` ∈ `session`, `in-session`, `wrap` (all in-session writes) | `source: manual-wrap` (what `/wrap` writes; `auto-wrap` and no source stay) | `{path, action:"source", before, after}` |
| `types` | `oldType`: frontmatter whose top-level `type:` is not `memory` or is missing (a host's auto-memory shape) | `type: memory` (replaced, or inserted as the first key); `tags:` gains `memory/<type>` (a missing `tags:` becomes `[memory/<type>]`); no status is invented, since `status/active` would put an old project into BRAIN.md's Active context unasked; `name:`, `description:`, `metadata:` stay | `type` (before the old value or null) and, when it changed, `tags` (the old and new line values) |
| `descriptions` | `noDescription`: a memory with frontmatter but no `description:` of its own while its MEMORY.md line has one | `description:` = that line's, one line, control characters out, ≤ 200 characters (memory-ops `keepDescription`), quoted only when strict YAML needs it (memory-ops `yamlValue`, also used by `set` and archive) | `{action:"description", before:null, after}` |
| `index` | `unindexed`, `misfiled`, `brokenIndex` | under one MEMORY.md lock: a missing line inserted under its type's heading (`indexLine` from the H1 and the description, else `deriveDescription(firstParagraph)`); a misfiled line moved, text unchanged, under its own heading; a line removed when nothing at all is at its path (`brokenIndex` counts only those: a link or a file too big to read is not broken), when its memory is archived or superseded, or when it is a second misfiled copy (each `index-remove` row says why: `reason` `missing`, `retired`, `duplicate`); a bullet that links the memory some other way counts as its line (`linkedPaths`, memory-index.js's rule), so nothing is added twice. A `MEMORY.md` with CRLF throughout keeps CRLF | `index-add` (after: the line), `index-move` (before/after: the headings), `index-remove` (path `MEMORY.md`, before: the line) |
| `drafts` | `leftoverDrafts`: a draft with the slug and the title (spaces folded, case ignored) of a live feedback memory; a new rule that only shares the slug is kept | the draft file removed (regular file, plain folder, O_NOFOLLOW read; spec §6's one delete) | `{path:"brain/memory/feedback/_drafts/<slug>.md", action:"draft-remove", before: its title, after:null}` |

JSON (`--json`, both modes): `{kind, dryRun, changes, files, expect, brainMd}`; `expect` is the changes' hash, which the page passes back with the real run (`--expect`): it refuses (`CHANGED`, nothing written) unless it would make exactly those changes; `files` counts changed files (MEMORY.md once); `brainMd` is build-brain-md's run after a real `types` or `index` run with `files > 0` (`{ok, error?}`), else null. Trail: one row per changed memory or draft, `{action:"fixed", kind, slug, type, title, path, changes:[{field, before, after}]}` through memory-ops `appendTrail` (a draft's row has `type: "feedback"` and its slug; `index-remove` rows have no slug, `path: "MEMORY.md"`). Errors as the other verbs: a usage error exits 2, a refusal (MEMORY.md a link, `brain/_index` missing) `aos: <msg>` exit 1. `--dry-run` is now `set`'s and `fix`'s flag. The HUD shows a `fixed` row in a memory's history as "fixed (<kind>)" (brainModel `historyLine`).

**`brain-map.json`** (`lib/brain-map.js` `buildBrainMap({vault, cfg, memories, now})`, called by `buildBrainHub`, written beside `brain-hub.json` with `fsx.writeAtomic`; the scan's `brain-hub` stage adds it to `wrote`). Input: `<vault>/<graph.out>/graph.json` through `sdk/lib/graph.js` (`outDir`, `loadGraph`) and the live memories (`ops.listMemories`). Shape: `obsidian-plugin/src/data/brainModel.ts` `BrainMap` (the HUD's parser is the contract). Steps:
1. `state`: `"off"` when `graph.enabled === false`; `"missing"` when no readable graph.json; else `"ok"` with `graph: {builtAt, mode, nodes, edges, communities}` (the marker `.aos-graph.json` for `builtAt`/`mode`, else the file's mtime and null). Not ok: every list empty, counts 0.
2. Hubs: nodes whose `source_file` is `MEMORY.md`, `brain/_index/MOC-*.md` or `brain/_index/BRAIN.md`; they and their links are dropped; `hubs` lists the files found. A hub community is any graphify community holding a hub node.
3. Memory units: a live memory's nodes are those whose `source_file` is its path. Memory links: a graph link between nodes of two different live memories (counted), plus two memories sharing one non-memory, non-hub neighbour node (counted once per shared node; a node touching more than 40 memories is a hub-like concept and is skipped).
4. Community: the most common community among a memory's own nodes outside hub communities; else the most common among its linked neighbours' nodes outside hub communities (weighted by link count); ties go to the lower id; none → null. Kept: communities with ≥ `memory.mapMin` memories, as `c<id>`, largest first (ties by id); the rest count in `smaller`, and their memories get `community: null`.
5. Per community: `paths` by degree (distinct linked memories) then path; `lead` the first; `name` its title (memory-ops `titleOf`); `edges` the links inside. `links`: memory links between two kept communities, summed, `a < b`. `memories[p]`: community, degree, ≤ 12 neighbours by count then path. `unlinked`: live memories in the graph with degree 0.
Size on the real vault: about 350 memories, under 100 KB. No model call; deterministic for one graph.

**Decisions made while building.**
- `fix index`: a misfiled line of an archived or superseded memory is removed (`index-remove`, path `MEMORY.md`), not moved, since a retired memory has no line (D5, D7); its file is untouched. A line is removed as broken only when nothing at all exists at its path.
- `brain-map.json`: an archived or superseded memory's nodes drop out as if the file were deleted, so a retired memory never links two live ones. The returned hub carries the map unenumerated (`hub.map`) for the scan's report; `brain-hub.json` stays the hub alone.
- Bootstrap computes "looks shipped" from the files with the same `SHIPPED` as `brain-hub.js` (a project marked complete leaves at once, not at the next scan); Active context has All / Looks shipped chips, where "Review the N…" lands.
- "Unused" means one thing across the hub: Library's Use facet and row label follow `memory.neverUsedDays` as Dead weight does (brainModel `usedWithin`; at the default 30 it is the hub's `d30 === 0`), so "Review the N" opens exactly N. MEMORY.md's line count is its non-blank lines in Bootstrap and Health alike (`indexLineCount`).
- An approved feedback draft logs a `written` trail row; `/wrap` (`wrap-session.js`) also rebuilds the hub when it promotes something, logging a failed rebuild to stderr.
- Review fixes (2026-10-11): the hub lists only what a fix acts on (a `noDescription` memory has frontmatter; `brokenIndex` is a line with nothing at its path; a draft is left over only with its rule's title too), so the badge can reach zero; `entryOf` reads a bracketed title, a CRLF line and a typed ` - `; `healthCount` leaves `noDescription` out (every writer leaves a new memory's description to MEMORY.md, and every list reads it from there), while Hygiene still lists it; `yamlValue`'s last resort is a single-quoted scalar with `'` doubled, which every reader here reads back; `aos memory set --skip-brain-md` lets Bootstrap's bulk Mark complete rebuild BRAIN.md once (the brain surface runs `build-brain-md.js`, as Pulse does); a row's verb keeps the row, busy, until it answers, and row buttons ignore a double-click's second click; Library hides use with telemetry off; the HUD names `/wrap` as the hosts invoke it (BrainSettings `wrapHint`).

### Mechanics

**Verbs** (`cli/memory.js`; `--json` prints one object; errors `aos: <msg>` exit 1; usage exit 2). `--estimate` is a new boolean flag (merge-draft, sweep), `--into` a value flag (merge, already global in `cli/aos.js`).

| Verb | Writes | JSON |
|---|---|---|
| `merge-draft PATH{2–6} --estimate --json` | nothing; no model call; resolves the provider (may refresh `provider-state.json`, as any resolve does) | `{winner, type, sources, baseHashes, byHand, truncated, estimate}` |
| `merge-draft PATH{2–6} --json` | nothing but the spend ledger row of its one call | `{winner, type, sources, baseHashes, truncated, mode, reason, provider, model, usd, estimated, cap, fields, generatedAt}` |
| `merge PATH{2–6} --into JSON --expect H,H,… --json` | the record, the winner, the losers (D7), MEMORY.md, the trail; rebuilds BRAIN.md | `{path, superseded, record, hash, brainMd}` |
| `unmerge PATH --expect HASH --json` | the winner back, the losers restored, MEMORY.md, the record (`undoneAt`), the trail; rebuilds BRAIN.md | `{path, restored, record, hash, brainMd}` |
| `sweep PATH{0–50} --estimate --json` | nothing; no model call | `{scope, considered, of, estimate}` |
| `sweep PATH{0–50} --json` | `brain/_index/memory-sweep.json` and the ledger row | `{run, suggestions}` (the run and its new cards) |
| `sweep dismiss ID --json` | `memory-sweep.json` | `{dismissed, already}` |

`set`'s `--set` gains `title` (one line, 1–120 characters, no control characters): the body's first H1 is rewritten (or a `# <title>` line is inserted after the frontmatter when there is none), and the MEMORY.md line is upserted with the new title and the line's description (else the memory's). The trail row is `set` with `fields: ["title"]`.

**Shapes.**
- `source`: `{path, title, type, created, hash, chars, truncated}`: `chars` the body characters sent; `truncated` true when the 8,000 cap cut it.
- `Estimate`: `{available, reason, provider, model, tokensIn, tokensOut, usd, cap}`.
  - `provider` ∈ ollama · claude · codex · none.
  - `reason` is null when available, else one of the provider's reasons (`forced`, `daily-cap`, `reasoner-daily-cap`, `no-provider`, `claude-not-logged-in`, `codex-not-logged-in`, …) or `ollama-only` (the sweep with only Ollama, A7).
  - `usd` is the estimate (6 places), 0 for Ollama.
- `cap`: `{family: "hook"|"codex"|"reasoner"|"reasoner-codex"|null, perDayUsd, spentToday, perCallUsd}`. It is null for Ollama; `perCallUsd` is null under Codex (no per-call cap).
- `byHand`: `{title, description, body}`, the no-model prefill (A4).
- `mode`: `ai` or `by-hand`. `by-hand` comes with a `reason` sentence the page shows, and `fields` = `byHand`.
- The reason sentences:
  - "No model provider is set up."
  - "Today's model cap is reached ($0.50, claude.perDayUsd)." (or `codex.perDayUsd`)
  - "Claude Code is not signed in." / "Codex is not signed in."
  - "<Provider> did not answer."
  - "The model's reply could not be read."
- `fields`: `{title, description, body}`.
- `usd`: the call's real cost (Claude `total_cost_usd`), else the priced usage (Codex, `estimated: true`), else 0 (Ollama, by-hand).
- `cap` after the call is re-read, so the page can say "today $y of $z".
- `run`: `{id, at, scope, provider, model, usd, estimated, considered, of, suggestions}`; `suggestions` is the count; `scope` is null for the whole vault, else `{paths}` (the page passes a community's or a cluster's paths, lead first).
- A card: `{id, run, kind, paths, hashes, title, description, why, scope, state}`.
  - `kind` ∈ merge · archive · retitle; `state` ∈ open · dismissed.
  - `title` is `""` when the card has none (merge: the proposed title; retitle: the new title); `description` is `""` or retitle's new description.
  - `scope` is the run's scope paths key (`null` | the sorted paths joined by `\n`, sha256, 12 hex).
  - `id` is `sha256(kind + "\n" + sorted paths.join("\n")).slice(0, 12)`.
- `memory-sweep.json`: `{schema: 1, runs: [run…] (newest first, ≤ 20), suggestions: [card…]}`.

**Merge rules (A1, A8, A9).**
- **Paths:** 2–6 distinct, all live (a retired one refuses `GONE`), all with frontmatter (`NO_FRONTMATTER` refuses: "run Health's fixes first").
- **Winner:** the oldest by `created:` (a date or ISO time; missing sorts last), ties by path. The winner's type is the merged type.
- **Prompt:** one block per source, `=== <path> (<type>, created <created>) ===`, then the title, the description and the body.
  - The body has no frontmatter and no leading H1, and is cut at 8,000 characters with `\n[… cut]`.
  - All blocks together are cut at 24,000 characters, newest source first.
- **Reply schema (strict):** `{title: string ≤ 120, description: string ≤ 200, body: string ≤ 16000}`, all required, no other keys.
- **Clean:** the title and description become one line with control characters out and are trimmed (title ≤ 120, description ≤ 200). The body gets CRLF → LF, a leading `---…---` block or lone `---` line dropped, a leading H1 dropped, trimmed, and is cut at 16,000.
- **A bad reply** is one that is not JSON, has an empty title or body, or has extra keys after the schema. It gives `by-hand` with "The model's reply could not be read."
- **`byHand`:**
  - the winner's title and description (its key, else its MEMORY.md line, else derived from its first paragraph);
  - the body: the winner's body (no H1), then per other source in age order `\n\n## From <title>\n\n<body without H1>`;
  - cut at 16,000.
- **`merge --into`** is a JSON object with exactly `title`, `description` and `body`, validated as Clean (refusing, not cutting: `BAD_FIELD`). `--expect` holds the hashes in path order, comma-joined (16–64 hex each, one per path): a count mismatch is a usage error, and a changed file is `CHANGED` naming it ("<path> changed since it was read: open the merge again").
- **The winner's new text:** its frontmatter lines are kept, then:
  - `description: <yamlValue>`, `reviewed: true` and `updated: <today>` are set;
  - `pin: true` is set when any source is pinned;
  - the body becomes `# <title>\n\n<body>\n`.
- **The record:** `brain/_index/memory-merges/<id>.json` (`id` = `<YYYYMMDD-HHMMSS>-<sha256(paths).slice(0,8)>`) holds `{schema: 1, id, at, winner, before: {text, hash}, after: {hash}, sources: [{path, hash}], undoneAt: null}`. It is written with `fsx.writeAtomic` before the winner. The folder is checked with `plainDir` and created plain.
- **Then:**
  1. the winner is written (atomic);
  2. each loser gets `status_before`, `superseded_by: <winner>`, `status/superseded`, and a description kept (as `retire`);
  3. under ONE `editIndex`, the losers' lines are removed and the winner's line upserted (`indexLine(title, winner, description)` under its type heading);
  4. the trail gets `merged` on the winner (`{from: [losers], record: id, hash: <after hash>}`) and `superseded` per loser (`{by: winner, record: id}`).
- **`unmerge PATH --expect HASH`:**
  - Finds the newest record whose `winner` is PATH and whose `undoneAt` is null, else `NOT_FOUND` ("no merge to undo for <path>").
  - Requires the file's hash = `--expect` = `record.after.hash`, else `CHANGED` ("<path> changed since the merge: undo it by hand").
  - Writes `before.text` back and restores the losers that still say `superseded_by: <PATH>` (restore's rules: their status and lines back).
  - Upserts the winner's line from its old title and description.
  - Sets `undoneAt`, and writes the trail row `unmerged` (`{record, restored}`).
- **Prune:** records older than 30 days (by `at`) are removed by `brain-hub.js` each build, failures swallowed. They are regular files in a plain folder; nothing else is deleted.

**Sweep rules (A6, A10, A11).**
- **Input:**
  - One line per live memory: `<path> | <type> | <status or active> | <age in days> | used <d30 or "?"> | <title> | <description> | <first 200 characters of the body, one line>`, where usage comes from `brain-hub.json`, else `?`.
  - Then `PAIRS:` the hub's duplicate pairs among them (`a b score`) and `CLUSTERS:` its clusters (paths).
  - A scoped run sends only those paths (every one must be live; ≤ 50), with its pairs and clusters.
  - Cap: 120,000 characters. Past it, memories are taken in order: in a pair or cluster, then unreviewed, then newest. `considered` counts what was sent, `of` counts the scope.
- **Reply schema (strict):** `{suggestions: [{kind, paths, title, description, why}] ≤ 20 (10 scoped)}`, with `kind` an enum, `paths` 1–10 strings, the strings `""` when unused, and `why` ≤ 200.
- **Keep a card only when:**
  - its paths are all in the input and live;
  - merge has 2–6 paths, archive 1–10, retitle exactly 1 with a title (1–120, one line) that differs from the current one;
  - the `id` has not been seen in this reply;
  - the `id` is not a dismissed card.
- **Store:**
  - `hashes` are the current hashes, `state: "open"`;
  - this run's scope replaces the open cards of the same scope; other scopes' cards and every dismissed card stay;
  - `runs` keeps the newest 20;
  - the write goes through `fsx.updateSync` (lock, atomic).
- **Off:** with no Claude or Codex for the reasoner role (`none`, a cap, Ollama only), the real run refuses with `aos: the sweep needs Claude or Codex (<reason sentence>)`, exit 1. `--estimate` says `available: false` with the reason.
- **`dismiss ID`:** `ID` is 12 hex. It sets `state: "dismissed"` (`already` when it is), and `NOT_FOUND` when no card has it.

**The AI seam: `lib/memory-ai.js`** (both verbs; tests inject `opts.ai`):
- **`resolve(kind, {deps})`:**
  - `kind` ∈ `merge` · `sweep`.
  - merge → `provider.resolveProvider({feature: 'memory-merge', deps})` (the hook chain).
  - sweep → `provider.resolveProviderForRole({role: 'reasoner', feature: 'reason:memory-sweep', deps, hostOpts: {claude: {model: cfg.claude.model, effort: null}, codex: {model: cfg.codex.model, effort: cfg.codex.effort}}})`.
  - A sweep that resolves to Ollama or `none` is `{available: false}`.
- **`estimate(kind, {chars, outTokens, deps})`** → `Estimate` (above):
  - tokensIn = ceil(chars / 4) + OVERHEAD[provider] (claude 600, codex 20,000 counted as cached, ollama 0);
  - priced by `model-pricing.priceUsd(provider, model, usage)`;
  - `cap` from the provider's budget (spentToday through `spend-ledger`).
- **`call(kind, {system, prompt, schema, timeoutMs, numPredict, deps})`:**
  - Returns `{text, provider, model, usd, estimated, cap}`.
  - Wraps `deps.claudeCall` / `deps.codexCall` as `workspace-draft.js:253-259` does, to catch the usage.
  - Codex runs in an empty temp folder.
  - It throws the provider's `ProviderUnavailable` (`PROVIDER_NONE` · `PROVIDER_CAP` · `PROVIDER_UNREACHABLE`) unchanged.
- **Labels:** `who(p)` → `{provider, model}` (Ollama's model is `role('workhorse').tag`). `reasonSentence(reason|error, cfg)` → the sentences above.
- **Timeouts:** merge 90 s, sweep 120 s. `numPredict`: merge 2,000, sweep 3,000.
- **`provider.js`** gains `hostOpts` on `resolveProviderForRole`: per host, a `model` (a non-empty string replaces the role's model; a Claude alias never reaches Codex because each host has its own entry) and an `effort` (null = no `--effort` for Claude; a Codex level for Codex). `prefer`, `model` and `effort` keep their meaning, and `hostOpts` wins when both are given.

**`sdk/lib/model-pricing.js`.** `RATES_AS_OF`; `claudeRate(model)` → `{model, in, out, matched}`:
- aliases haiku → `claude-haiku-4-5`, sonnet → `claude-sonnet-4-6`, opus → `claude-opus-5`;
- else exact, else the longest prefix (`claude-haiku`, `claude-sonnet`, `claude-opus`, `claude-opus-4`), else `claude-sonnet-4-6` (pricing.json's `default_model`).

`priceUsd(provider, model, {inputTokens, cachedInputTokens, outputTokens})`:
- Claude: input at `in`, cached at `in × 0.1`, output at `out`;
- Codex: `codex-pricing.priceUsd`;
- Ollama: 0.

A test pins every model in the repo's `extras/cost/pricing.json` to the same rates and the same default (the runtime does not read that file: `extras/` is not vendored).

**Surface (`brain`).**
